# 场地基本资料提取与从业者覆核

更新：2026-09-22。状态：规格草案；A/K1/265 样板待从业者覆核，未开始实现。本文和 companions 构成下一轮需求契约，未决问题不代表已获确认。

## Why

规划从业者需要从已搜集文件中形成可核对的场地基本资料表，回答场地身份、用途、规模、参数含义、规划依据、申请历史及未决问题。主要成果是带时间、资料性质、来源和覆核状态的结构化资料；高亮负责回到原文，从业者确认或修正结果。持续使用时，本机容量可控且研究证据可恢复。

## Capabilities

- **CAP-1**
  - **intent:** 从业者能从资料表或候选重点准确返回原文证据。
  - **success:** 每条可展示高亮绑定具体文件版本、页码、原文区域及摘录；跳转后吻合原文。无法定位的建议不伪装成有效高亮。
- **CAP-2**
  - **intent:** 从业者能区分资料和段落的角色，避免把陈述、建议或招商参数当成正式决定。
  - **success:** 文件类型与段落角色独立记录；申请人陈述、补充资料、部门意见、职员建议、会议决定、撤销／失效及意向／招标资料分别标记；候选类别和未知状态可覆核修正。
- **CAP-3**
  - **intent:** 从业者能确认、修改及移除字段提取结果和高亮建议，并保留操作历史。
  - **success:** 字段值、时间、资料性质、来源关联及高亮的修改均保留前后值；重启后操作保持；移除可恢复；重新分析产生新结果，不覆盖人工覆核或复活已移除项。
- **CAP-4**
  - **intent:** 从业者能分别核实 OZP、Notes、BO、Lands 与研究问题的关系。
  - **success:** OZP／Notes、规划申请与决定、BO 建筑记录、Lands 契约与批准形成四条独立证据链；各有证据或明确缺口，不能互相替代。适用性记录包含范围、时间、版本、理由、原始依据和覆核状态；缺文件、未研究、不适用及来源冲突分别显示。具体边界见 reference-scope.md。
- **CAP-5**
  - **intent:** 用户能限制缓存增长，保留研究证据。
  - **success:** 原件按需下载，相同内容物理去重；缓存清理不删除高亮、覆核、引用或手动保留依赖的原件；没有可清理空间时暂停新增占用并说明原因。
- **CAP-6**
  - **intent:** 用户能把完整项目归档到外置存储，并恢复继续研究。
  - **success:** 原件哈希、来源、版本、锚点、覆核历史和分析结果恢复一致；校验失败不释放本地副本；断盘可识别为离线。
- **CAP-7**
  - **intent:** 用户能重现已保存的研究结果，并追踪重新分析的差异。
  - **success:** 保存输入哈希、工具与模型标识、配置规则版本及输出；无需再次推理即可恢复旧结果，新运行有独立标识。

- **CAP-8**
  - **intent:** 从业者能取得场地身份、用途和发展规模的基本资料表。
  - **success:** site-information.md 中各字段均有提取结果或明确缺口；每项作为有出处的主张保存时间、资料性质、来源、覆核状态、范围、阶段、陈述者、约数／不等号、分母及被取代关系；不同方案和冲突数值不合并，变更原因可追踪。
- **CAP-9**
  - **intent:** 从业者能追踪申请历史、条件以及仍需核实的问题。
  - **success:** 历次申请、决定、有效期、撤销、续期、批准条件和部门意见按关联与时间保存；数字冲突、未知口径、缺失文件及 BO／Lands 待查事项逐项显示。需付费、业主授权或部门协助取得的资料进入请求清单，解决后保留依据和操作历史。

## Constraints

- 每项字段区分现状、申请方案、批准内容和规划上限；计算值另存公式及输入来源，未知不替换为零或不适用。
- 参数是来源在特定时间、阶段和范围作出的主张，不预设唯一场地真值。面积口径、单位、边界和高度基准保留，不以申请面积自动代表整幅地段，不以方案 PR 冒充法定上限。
- 保留约数、不等号、脚注及 PR 分母。数字变化不自动解释为实体扩建；约数面积不得乘 PR 推导精确法定 GFA；“总楼面面积”无依据时不等同 GFA。
- 原件不修改；完整申请编号不按前缀合并；锚点不能跨版本静默迁移。
- 已有检索快照、来源、阅读状态与当前范围 ZIP 行为保持；测试不写日常库。
- 区分事件、文件、获取及适用时间；历史申请的引用不等于现行资料。
- 存储清理必须检查所有项目、历史版本及进行中任务的引用；受保护资料不能因超额而自动删除。
- 有界并发、分阶段处理并记录资源使用；容量耗尽及中断不得损坏已提交成果。
- 分析采用 Kimi 云端 API。默认仅在用户发起分析时发送完成该次任务所需的提取文字及上下文；请求范围可见、可追踪。Kimi Code 订阅接口为候选，适用性与账户权限核实前不将其作为已获准的产品运行渠道；见 kimi-integration.md。
- OCR 仅在文本提取不足以支持必填字段时按页启用，并记录覆盖、工具配置及覆核；同一官方来源的重复阅读不算独立交叉验证。
- 系统不得静默购买文件、使用私人账户或把一般政策当作个案证明；付费或受限取得工作进入请求清单。

## Non-goals

- 本轮不实施代码，也不宣称已完成真实案例验收。
- 不自动作最终专业判断，不承诺全港资料或历史版本完整覆盖。
- 不做地址反查、多用户云服务、全量预索引、通用图则视觉理解或独立三栏重做。
- 不保证模型重新运行逐字一致；不把外置归档当作额外备份。

## Success signal

从业者在 A/K1/265 的冻结官方资料上，获得覆盖七类问题的场地资料表；逐项核对值、单位、范围、阶段、时间、资料性质、出处及覆核状态，点击证据能回到对应原文。完成确认修改移除后，经重启、重分析、缓存清理和外置恢复，字段及人工成果保持一致；冲突与缺口不被隐藏。样板可在尚未设定任意数值阈值前制作；量化门槛在金标准和本机基准完成后、模型比较前固定，见 acceptance.md。

## Assumptions

- 使用目录 practitioner-review 和真实案例 A/K1/265；样板列明 2026-09-05 取得的本地官方文件哈希及版本，见 case-ak1-265.md，不将其特殊程序写成通用规则。
- “当前”默认指样板建立时明确记录的 as-of 日期；无法证明的精确边界或现状转成 ResearchIssue，不阻塞建立样板。
- 架构提案沿用 FastAPI、SQLite、本地文件和 PDF.js；模型接入 Kimi API，模型编号及提取库待接入验证，分析引擎须可替换。
- 先前记录的 8GB RAM 仅是待测背景。资源预算以实际机器和真实样本的峰值内存、临时磁盘、耗时及交互响应确定；试点优先文本 PDF，必要页面才启用 OCR。

## Open Questions

- Q1：Kimi Code 订阅条款及本人账户是否覆盖此个人交互式规划资料分析工具？接入时实测认证、权限及配额；如不覆盖，改用 Kimi Platform API。页面图像或整份原件外发不在当前默认范围。
- Q2：A/K1/265 金标准和本机基准完成后，采用哪些字段准确率、覆盖率、定位成功率、耗时和存储量化目标？
