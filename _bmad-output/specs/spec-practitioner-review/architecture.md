# 架构说明

本文件为待验证设计提案，非现有实现。基线代码位于 app/store.py、app/library.py、app/research.py、web/reader.js：已有内容哈希存储、检索快照和阅读器；尚无本规格的高亮覆核实体。旧功能保留，新增关系逐步引入，不能直接重写历史 JSON。

## 边界与实体

| 实体／组件 | 职责与必要数据 |
|---|---|
| DocumentVersion | 逻辑文件、内容哈希、格式、来源、获取时间及存储位置；不同来源共用字节时仍保留各自出处 |
| Extraction | 输入版本、提取工具版本、逐页文本与原始坐标、旋转和裁切信息、失败页及覆盖范围 |
| Anchor | 文件版本、页索引与显示页码、一个或多个区域、原文摘录和上下文；不是可变页码字符串 |
| AnalysisRun | 输入版本集合、研究问题与时点、工具／模型标识、规则或提示版本、参数、原始输出、错误及覆盖范围 |
| SiteFact | 字段主张及元数据，具体契约见 site-information.md；包含 scope_kind、source_stage、asserted_by、approximation、denominator、supersedes、conflict_reason，关联版本锚点、分析运行、研究范围、方案与事件，一字段可多值 |
| ApplicationEvent | 完整申请编号、事件类型、决定和期限、条件及部门意见、证据关系；不覆盖较早事件 |
| ResearchIssue | 冲突或缺口类别、关联字段与证据、状态和解决操作记录 |
| Suggestion | 分析运行、锚点、文件及段落角色、候选理由、匹配校验结果 |
| ReviewEvent | 字段或建议 ID、确认／修改／移除／恢复、前后值、本地覆核者标识、时间；追加保存，不覆盖旧事件 |
| ApplicabilityRecord | 参考类别、研究范围和时点、具体版本、依据锚点、关联理由、候选／确认／排除／缺资料状态及覆核事件 |
| EvidenceChain | OZP／Notes、规划申请与决定、BO 建筑记录或 Lands 契约与批准；记录覆盖范围和独立佐证，禁止以一链替代另一链 |
| RecordRequest | 地址、PRN、lot／DD、所需文件、覆盖时点、预计费用、未决问题、取得限制、状态及取得后的来源；只管理请求，不自动购买或登入私人账户 |
| StorageLocation／Protection | 本地或外置位置、可用状态、引用和保护原因、进行中锁；全局判断能否释放物理文件 |

文件角色与段落角色分开：同一主文件可能同时含申请人陈述、部门意见与建议。模型返回文本候选，由定位层映射原文；禁止直接信任模型给出的坐标。无法唯一匹配或缺页时保留诊断，不渲染错误高亮。

## 分析与覆核

原件取得 → 哈希及格式验证 → 原生文字及页面结构提取 → 对必填字段缺口按页触发 OCR → 字段、角色及重点候选 → 原文匹配与口径检查 → 保存资料表和建议 → 人工覆核。OCR 运行保存覆盖页、工具与配置、输出和覆核状态；扫描页不能因无文字层而被当成空白。

提取、OCR、推理、定位相互独立，可暂停和按阶段恢复。优先复用与输入哈希及工具配置一致的结果。模型重跑创建新运行，保存旧输出；同版本相同锚点和类别可作候选匹配，含歧义的对应由人处理，不隐式继承确认。移除记录防止旧建议重新出现；对真正变化的新候选标明来自新运行。分析引擎通过稳定接口替换；本地保存不代表获准向外部服务发送原件、页面或文字。

原文摘录不可被人工备注替换。修改区域、角色或说明记录为覆核事件；新文件版本建立新锚点，旧版结果仍可查看。已保存输出的复现不依赖模型服务仍可用。

## 存储策略

- 设置独立缓存上限及可用磁盘保留量，数值待定；统计缓存、受保护原件、索引／覆核记录、派生数据和临时文件，分别显示实际物理占用。
- 清单不要求下载原件；打开或分析时下载。批量保存为明确操作，先估算占用，未知大小采用流式限额并预留临时空间。
- 相同内容只存一份。清理按较久未使用排序，但必须排除所有项目及历史引用中的保护项和活动任务。
- 创建候选前临时锁定原件；候选与保护关系一并提交。失败释放临时锁；删除候选不自动解除审计所依赖的保护。
- 清理与新保护提交协调，不能先判断可删再与覆核并发删除。中断恢复先校验锁和任务，不能删除正在使用的证据。
- 可再生成的页面图像及临时 ZIP 可清理；锚点复原所需的坐标映射、原始分析输出和覆核记录不是临时缓存。
- 若受保护资料占满空间，暂停新下载／分析并提供归档入口。缓存上限不承诺整个资料库永久不增长。

## 外置归档与恢复

冻结一致的项目快照，生成带格式版本的清单，包含原件、来源、检索版本关系、分析、锚点、覆核及适用性记录。复制至外置位置后检查全部哈希和关系，再在隔离位置恢复演练；用户选择释放本地后才处理可释放副本。其它项目仍需本地文件时不得删除共享原件。

归档中途拔盘、校验失败或空间不足均保留本地有效副本。保存归档身份和可重新定位的位置，不把绝对盘符作为唯一身份。断盘后本地目录仍可查看项目索引，打开原文提示接入存储；不能从官网取新版本冒充原件。归档是存储迁移，另行备份是否需要由用户决定。

## 资源与演进

先以一个重型分析任务、按页提取、按需 OCR 和按需渲染作为保守试点配置；保持有界并发。用 A/K1/265 冻结样本在实际机器记录峰值内存、临时磁盘、耗时、页面交互响应、取消和恢复，再据此确定缓存和性能预算。长任务记录进度，界面不阻塞；退出后恢复已提交成果。基于现有 SQLite 和文件系统演进，迁移须备份、版本化、可恢复，回归旧检索和 ZIP。

Kimi API 为目标模型服务；具体模型编号、Kimi Code 订阅渠道资格、OCR 和提取库在接入验证中决定，当前不添加依赖。接入边界、请求内容和失败处理见 kimi-integration.md。OCR 是否运行由所需字段在特定页面的文字可用性决定，无须先向用户索取整案 OCR 选择。所有测试在隔离库；沿用不启动 Chrome 或多个调试窗口的项目约束。

## 场地资料表的证据链

SiteFact 为核心输出，高亮是其证据视图。字段引用一个或多个 Anchor；字段确认与高亮定位、参考适用性分别记录，不能用一次点击自动确认所有判断。研究边界在字段层显式引用，不扩张为整幅地段或整栋建筑。

计算字段保存公式、输入字段的不可变版本和舍入规则；修改输入产生新计算候选，已覆核旧结果不被重算覆盖。机器候选、人工修订和选用显示值分别保存；未知元数据保持未知。

字段和历史条件引用的原件、计算输入证据及适用性材料一并纳入全局保护、分析复现和归档关系。移除字段仍保留审计依赖。冻结归档和恢复检查增加字段、事件、问题和输入依赖关系，不能只恢复 PDF 与高亮。

## 四条证据链与取得请求

OZP／Notes 证明法定图则及条文，规划申请与决定证明个案程序及结果，BO 建筑记录证明建筑审批记录，Lands 土地文书及批准证明契约或地政安排。每条链独立记录覆盖范围、文件日期、研究 as-of 日期及适用理由；规划批准不能替代建筑或地政批准，网上查不到也不能直接推断不存在。

受限资料以 RecordRequest 排队：BO 可包括入伙纸、获批准一般建筑图则和改建／修订批准编号；Lands 可包括土地登记册、Government Lease／New Grant／Conditions、memorials、已签立 waiver／STW 及附图。请求完成后把实际取得文件转成 DocumentVersion 和证据关系；未完成时保持“待取得”，不得以一般政策文字填补。
